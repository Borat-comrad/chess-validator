\# Chess Validator



Учебный проект на Python для пошаговой реализации валидатора шахматных ходов.



Цель проекта — не создание шахматного ИИ, а изучение Python, алгоритмов, тестирования и архитектуры программы на реальной задаче.



Chess Validator развивается постепенно: новая архитектура появляется только тогда, когда её требует уже написанный код.



\## Текущее состояние



Текущий этап — \*\*v0.2: единый валидатор геометрии хода\*\*.



Проект умеет проверять геометрию движения всех шести типов фигур на условно пустой доске:



\* слон;

\* ладья;

\* ферзь;

\* конь;

\* король;

\* пешка.



Реализованы основные функции:



```python

movement\_ban()



bishop\_can\_move()

rook\_can\_move()

queen\_can\_move()

knight\_can\_move()

king\_can\_move()

pawn\_can\_move()



validate\_move()

invalid\_input\_square()

```



`validate\_move()` является единым входом в геометрические проверки: получает обозначение фигуры и координаты, выбирает соответствующий валидатор и возвращает `True` или `False`.



\## Формат ввода



Текущий консольный интерфейс принимает запись:



```text

B a1 - h8

```



где:



\* `B`, `R`, `Q`, `N`, `K`, `P` — обозначение фигуры;

\* `a1` — начальное поле;

\* `-` — разделитель;

\* `h8` — конечное поле.



Перед вызовом игрового валидатора проверяется корректность формата входных данных.



Например:



```text

B a1 - h8

```



— корректный формат.



```text

B potato - h8

```



— ошибка формата и до `validate\_move()` не доходит.



```text

B a1 - a1

```



— формат корректен, но сам ход недопустим, поэтому геометрический валидатор возвращает `False`.



\## Текущая архитектурная граница



Сейчас программа разделяет две задачи:



```text

пользовательский ввод

&#x20;       ↓

проверка и разбор формата

&#x20;       ↓

validate\_move()

&#x20;       ↓

валидатор конкретной фигуры

&#x20;       ↓

True / False

```



Парсер отвечает за то, чтобы передать игровому ядру корректно сформированные данные.



Функции `\*\_can\_move()` отвечают за геометрию движения фигур и не зависят от `input()` или `print()`.



\## Что пока сознательно не реализовано



Текущий валидатор ещё не знает реального состояния шахматной позиции.



Поэтому он пока не учитывает:



\* расположение остальных фигур;

\* препятствия;

\* реальные взятия;

\* цвет фигуры на конечном поле;

\* очередь хода;

\* шах и безопасность собственного короля;

\* рокировку;

\* взятие на проходе;

\* превращение пешки;

\* мат и пат.



Это не недостатки текущих функций, а задачи следующих этапов проекта.



\### Пешка



`pawn\_can\_move()` уже учитывает:



\* цвет (`w` / `b`);

\* направление движения;

\* стартовую горизонталь;

\* обычный ход;

\* геометрию взятия через `is\_take`.



При этом `is\_take=True` пока означает только геометрическую форму взятия. Наличие чужой фигуры на конечном поле ещё не проверяется, поскольку модели доски пока нет.



\## Следующий этап



Перед дальнейшим расширением текущий слой должен быть закреплён автоматическими тестами.



После этого следующий крупный вопрос проекта:



> \*\*Как представить текущую шахматную позицию?\*\*



Необходимо будет хранить информацию о том, какая фигура какого цвета находится на каждом поле.



Конкретная структура данных заранее не выбрана. Она будет проектироваться тогда, когда существующей геометрии впервые действительно понадобится состояние доски.



Следующий ориентировочный этап:



```text

v0.3 — представление шахматной доски

```



После появления доски станет возможен переход от простой геометрии к проверке препятствий и взятий.



\## Принцип разработки



Главный принцип Chess Validator:



> \*\*Не подстраивать код под заранее придуманную архитектуру. Архитектура должна возникать из реального развития проекта.\*\*



Новая функция, структура данных, модуль или класс появляются только тогда, когда в существующем коде возникает понятная проблема, которую эта сущность решает.



Проект используется одновременно как программа и как учебная среда для изучения Python, тестирования, Git и инженерного проектирования.
